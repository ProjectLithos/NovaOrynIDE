# NovaOryn 0.1.1

NovaOryn 0.1.1 is the integration correction for the physical-memory work introduced in 0.1.0.

## Kernel integration

The authoritative bootstrap kernel, command-line editable template and Visual Studio editable template now call `KernelPhysicalMemory.Initialize(boot)` after the descriptor/interrupt-controller bootstrap and before the terminal halt. The call consumes the retained final UEFI map only after `BootContext.HasFinalMemoryMap()` has confirmed successful `ExitBootServices` hand-off.

`NovaOryn.Kernel.Memory` is a freestanding no-standard-library support assembly. Its default early manager uses sorted free extents and fixed kernel-resident metadata rather than a managed heap. UEFI ConventionalMemory and non-runtime BootServicesCode/BootServicesData become allocatable; loader, runtime, ACPI, MMIO, persistent, unusable and other firmware-owned ranges remain unavailable. The manager exposes initialization status, statistics, aligned contiguous allocation and validated one-time release.

This bootstrap manager is deliberately separate from the replaceable `NovaOryn.Memory.Physical` SDK contracts introduced in 0.1.0. It provides the default no-GC path required by the current editable freestanding kernel while later address-space work can bind the richer allocator contracts into the kernel runtime without introducing a heap dependency.

## Visual Studio reference loading

The VSIX template continues to place SDK implementation projects beneath the generated project's `Sdk` directory. 0.1.1 adds `NovaOryn.Kernel.Memory` to that tree and to the user project reference set.

The extension now detects NovaOryn projects in an open solution and loads every SDK-owned `.csproj` under that project's `Sdk` directory into the solution through Visual Studio's project system. It performs this both when the package first loads and when projects are subsequently added. A recursion guard prevents the synchronisation operation from re-entering while Visual Studio reports the projects being added.

This means separated SDK projects are real loaded solution projects rather than unresolved project-reference entries. Command-line projects generated by `NovaOryn.ProjectCreator` also receive a solution containing the separated SDK projects.

## Template acceptance

The editable kernel now visibly reports:

- final UEFI map retained;
- GDT/TSS installed;
- IDT installed;
- legacy PIC masked / APIC-MSI controller layer ready;
- physical memory manager initialized from the final UEFI map;
- CPU halted.

The user-owned file remains `Kernel\Kernel.cs`; SDK refresh continues to preserve that file while replacing the SDK-owned `Sdk` tree.

## Release scope

0.1.1 does not add virtual memory, a kernel address-space layout, a heap, ACPI reclaim, SMP frame caches or user-space memory policy. The next architecture stage remains kernel address-space design, followed by virtual memory management.
