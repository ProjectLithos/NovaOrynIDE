SDK architecture

NovaOryn separates reusable mechanisms from the user-owned operating-system policy. Architecture-specific operations live behind architecture contracts; kernel services consume those contracts; device families are split into their own assemblies; and generated projects select which facilities are part of the final OS.

Architecture layer

The x64 implementation covers processor operations, GDT/TSS descriptors, IDT/exception entry, low-level platform bindings and interrupt-controller integration. ARM64 currently exposes the architecture lifecycle scaffold and contracts without pretending unsupported native operations are complete.

Kernel mechanism layer

Memory, ACPI, scheduling, protection, system calls, processes, drivers, storage, networking, graphics and time are independent SDK facilities. This keeps the user kernel from needing direct CPUID, RDTSC, CMOS, MMIO, port-I/O or page-table manipulation for ordinary OS construction.

Driver boundary

Drivers register through the generic driver framework and request interrupt delivery through the opaque interrupt broker. A driver does not need to know whether a route is delivered by I/O APIC, MSI or MSI-X.

.NET compatibility

Freestanding code uses normal .NET-compatible primitive and value semantics wherever possible. NovaOryn.Freestanding.CoreLib supplies the freestanding surface required by NativeAOT rather than forcing kernel authors to use unrelated replacement types.
