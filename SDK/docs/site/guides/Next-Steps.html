Next steps

NovaOryn 0.29.0 already covers the major bootstrap-to-device path: memory management, ACPI, APIC-family interrupt routing, timers, SMP, scheduling, privilege separation, three syscall methodologies, process loading, driver registration, PCI/PCIe, storage, networking, USB, GOP graphics and VirtIO GPU.

Highest-value next SDK work

  • Debugging and diagnostics: structured traces, assertions, fault/crash capture, symbol-aware stack diagnostics and test harnesses.
  • Complete API documentation: many generated public items still show “Documentation pending”; strict documentation builds should progressively drive that count to zero.
  • Filesystem breadth and write support: retain the generic VFS/provider design while expanding beyond the current initial FAT32 reader.
  • Graphics: continue using generic framebuffer + VirtIO GPU for the common graphics contract before attempting vendor-sized Intel/AMD/NVIDIA driver projects.
  • USB depth: harden xHCI enumeration, hubs, HID and mass-storage behavior across more real controllers and devices.
  • Architecture expansion: complete native ARM64 mechanisms behind the existing architecture contracts without weakening x64 abstractions.

Keep policy outside the mechanism

Future work should continue the current direction: user-owned project configuration decides what belongs in a monolithic, microkernel or hybrid OS, while the SDK exposes reusable mechanisms and stable .NET-compatible contracts.
