Drivers, PCI and VirtIO

Generic driver framework

The driver framework owns device and driver registries, device identifiers/resources, matching and lifecycle callbacks. Registry storage can grow from the kernel heap by default, while fixed-capacity options remain available for deterministic configurations.

Interrupts stay opaque to drivers

Drivers request an interrupt through the broker. The broker decides whether the physical route uses MSI-X, MSI or I/O APIC delivery, so ordinary drivers do not contain controller-specific policy.

PCI and PCIe

KernelPci enumerates PCI/PCIe functions, reads and writes configuration space, discovers and sizes BARs, maps MMIO and walks capabilities. ACPI MCFG/ECAM is used where available, with conventional x64 configuration access available for compatible systems.

VirtIO

KernelVirtio implements modern VirtIO PCI transport and built-in block, network, console and entropy-source devices. The transport integrates with the generic driver framework, memory, storage, networking and time facilities.

Physical storage and network devices

The current SDK also exposes NVMe, AHCI/SATA, Intel E1000/E1000e and Realtek RTL8168/RTL8111-class driver assemblies.
