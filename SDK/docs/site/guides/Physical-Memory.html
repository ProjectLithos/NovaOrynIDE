Physical memory

NovaOryn exposes one common physical-memory contract with three built-in allocation methodologies: bitmap, buddy and extent.

Common contract

Higher-level SDK facilities can depend on IPhysicalMemoryManager. Built-in managers consume a normalized boot memory map plus caller-owned workspace, so allocator metadata does not depend on the later kernel heap.

Allocation constraints

PhysicalAllocationRequest can express contiguous page count, power-of-two page alignment, a minimum physical address, an optional exclusive maximum address and allocation purpose. This supports ordinary pages as well as constrained DMA allocations.

Ownership

Allocations and reservations use explicit ownership records/tokens so stale or double releases can fail deterministically rather than silently corrupting the free-frame state.

Choosing a methodology

  • Bitmap: simple per-frame state and predictable lookup over reasonably dense physical ranges.
  • Buddy: power-of-two blocks with split/coalesce behavior and natural alignment.
  • Extent: exact page counts and metadata that follows free-range fragmentation.
