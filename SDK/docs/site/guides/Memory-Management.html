Memory management

NovaOryn treats boot-map normalization, physical frames, virtual mappings, kernel address-space policy and heap allocation as separate layers. Higher layers should not need to understand UEFI descriptor formats or x64 page-table bit layouts.

Boot memory map

The boot layer retains the final firmware memory map and normalizes ranges before they are consumed by the physical allocator. Kernel image pages, boot structures, framebuffer/MMIO regions, page tables and allocator metadata must remain reserved rather than being returned as ordinary free frames.

Physical allocation

The SDK exposes IPhysicalMemoryManager and built-in bitmap, buddy and extent methodologies. Allocation requests can express page count, power-of-two alignment, minimum address and an optional maximum address, allowing constraints such as DMA memory below 4 GiB.

Virtual memory

The x64 virtual-memory layer works with the active CR3 hierarchy and supports 4 KiB, 2 MiB and 1 GiB leaves, mapping, unmapping, protection replacement, translation, canonical-address checks and TLB invalidation.

Kernel address space and heap

The address-space layer owns policy for reserved kernel virtual regions. The early allocator is used before the normal heap is ready; the page-backed heap then obtains physical backing through the PMM/VMM path instead of bypassing memory ownership.
